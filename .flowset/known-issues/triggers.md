# Known Issue Triggers — 해결 발동 정책

> 알려진 이슈를 언제 일괄 해소할지 정의. INDEX.md의 카운트가 본 규칙에 도달하면 `WI-KI-batch-NNN` 발동.

## 1. 심각도 정의

| 심각도 | 정의 | 예시 |
|--------|------|------|
| **P0 Critical** | 보안 취약점, 데이터 손실, 시스템 다운, 컴플라이언스 위반, 권한 우회 | RLS 누락으로 타 테넌트 데이터 조회 가능 / 평문 비밀번호 저장 / 결재 권한 우회 / GDPR 위반 |
| **P1 High** | 핵심 기능 결함, 권한 매트릭스 불일치, API 계약 위반, 데이터 정합성 깨짐 | spec §9 권한과 RLS 정책 불일치 / 결재 후 휴가 잔여 미차감 / API envelope 형식 위반 |
| **P2 Medium** | 비핵심 기능 결함, 사용성 저하, 한글 라벨 누락, 명세-구현 표기 불일치 | 일부 화면 영문만 노출 / 페이지네이션 페이지 사이즈 spec 위반 / 토스트 메시지 부재 |
| **P3 Low** | 리팩토링, 문서 보강, 마이너 UX, 비기능 최적화 | 동일 로직 2회 복사 (3회 미만) / 인덱스 추가 검토 / 토큰 만료 안내 문구 개선 |

## 2. 트리거 임계 (누적 건수)

| 심각도 | 임계 | 의미 |
|--------|------|------|
| P0 | **1건** | 즉시 차단 — 발견 즉시 batch WI 생성, 진행 중인 작업 일시 정지 |
| P1 | **3건** | 누적 3건 → batch WI 생성 |
| P2 | **5건** | 누적 5건 → batch WI 생성 |
| P3 | **10건** | 누적 10건 → batch WI 생성 |

## 3. 추가 트리거 (시점 기반)

이슈 누적 임계와 별도로 다음 시점에도 batch 발동:

| 시점 | 대상 | 조치 |
|------|------|------|
| **Phase 종료 직전** | P0 / P1 잔존 | 모두 0건이어야 다음 Phase 진입 |
| **Phase 종료 직전** | P2 / P3 잔존 | 다음 Phase 이관 가능, 단 INDEX 상태 명시 + 사용자 보고 |
| **Phase 7 (개발) 종료** | P0 / P1 / P2 잔존 | 모두 0건이어야 Phase 8 (QA) 진입 |
| **Phase 9 (베타) 진입 전** | P0 / P1 / P2 잔존 | 모두 0건이어야 베타 시작 |
| **Phase 10 (운영) 진입 전** | P0 / P1 / P2 / P3 잔존 | P0/P1/P2 0건, P3는 운영 백로그로 명시 이관 |
| **사용자 명시 요청** | 모든 활성 이슈 | 사용자가 호출하면 즉시 batch |

## 4. batch WI 생성 규칙

트리거 도달 시:

1. **WI 번호 부여**: `WI-KI-batch-NNN` (NNN = 001, 002, ... 누적)
2. **fix_plan.md 추가**: "## Phase X — Known Issue Batch" 섹션에 체크박스 추가
3. **사용자에게 보고**:
   - 트리거 종류 (P0 즉시 / P1 누적 / Phase 게이트 등)
   - 포함 이슈 ID + 제목 + 심각도
   - 예상 작업 범위
4. **사용자 승인 대기** (단, P0는 자동 승인 — 즉시 진행)
5. **수정 진행**:
   - 코드 변경분은 evaluator(code 모드) 검증
   - 문서 변경분은 evaluator(doc 모드) 검증
6. **아카이브**: 해결된 이슈를 `archive/YYYY-MM-DD-batch-NNN.md`로 이동, INDEX에서 제거
7. **카운트 갱신**: INDEX.md 카운트 표 재계산

## 5. 이슈 등록 출처

이슈는 다음 출처에서 등록됨 — 본 정보를 INDEX.md `출처` 컬럼에 기록:

| 출처 | 설명 |
|------|------|
| `evaluator` | evaluator 채점 시 NON_BLOCKING_OBSERVATIONS 또는 FAIL ISSUES 중 비차단 항목 |
| `claude` | Claude가 작업 중 자체 발견 |
| `user` | 사용자가 명시적으로 등록 요청 |
| `beta` | 베타 사용자 피드백 |
| `ops` | 운영 단계 인시던트 / 모니터링 |
| `audit` | 보안 감사 / 컴플라이언스 점검 |

## 6. 우선순위 재조정

이슈는 등록 후 다음 사유로 심각도 재조정 가능:

- **신규 정보 발견**: 영향 범위가 예상보다 큼/작음 → 승격/강등
- **다른 이슈와 결합**: 단독으로는 P2지만 결합 시 P1
- **시점 변경**: P3가 베타 진입 직전이면 사용자 가시 영향 커짐 → P2 승격

재조정 시 INDEX 상세 블록에 `재조정 이력` 라인 추가.

## 7. 에스컬레이션

- batch WI 1회 시도 후에도 evaluator FAIL → 재호출 (최대 3회)
- 3회 연속 FAIL → 사용자 에스컬레이션 (스코프 재검토 권고)
- P0 미해결 24시간 경과 → 사용자 알림 (라이트 모드는 수동 점검)
