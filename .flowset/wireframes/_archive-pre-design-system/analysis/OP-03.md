# OP-03 테넌트 상세 — 와이어프레임 분석

## PRD 1:1 매핑

| PRD § | 요구 | 구현 위치 | 상태 |
|-------|------|----------|:---:|
| §3-1 헤더 | 회사명 + 도메인 + 상태 배지 | `.tenant-header` | ✅ |
| §3-1 핵심 카드 3개 | 대표관리자 / 계약 정보 / 사용량 | `.info-cards` 3개 | ✅ 3/3 |
| §3-1 액션 5개 | 관리자/요금제/기능권한/비활성화/청구 | 헤더 하단 버튼 그룹 | ✅ |
| §3-2 탭 8개 | 기본/사용자/구독/청구/기능권한/사용량/감사/티켓 | `.tabs` | ✅ 8/8 |
| 기본정보 탭 콘텐츠 | 회사 정보 + 도메인/환경 | grid-2 레이아웃 | ✅ |
| §4 액션 6개 | 관리자/요금제/기능권한/비활성화/청구/회사명 | 헤더 + 탭별 수정 버튼 | ✅ |

## 탭 전환

- URL: `?tab={basic|users|subscription|billing|flags|usage|audit|tickets}`
- 브라우저 뒤로가기 보존 (PRD §8 Scenario 2)
- 본 와이어프레임은 "기본정보" 탭 활성 상태 (다른 탭은 콘텐츠 영역 교체)

## 인터랙션 동선

- 헤더 "비활성화" → 사유 모달 → confirm → tenants.status=inactive + 해당 테넌트 사용자 세션 즉시 무효화
- "요금제 변경" → OP-05 플랜 선택 모달 임베드
- "청구내역 보기" → OP-06 (`?tenant_id=...` 필터)
- "기능권한 수정" → OP-07 일부 임베드 또는 신규 탭
- breadcrumb "테넌트" 클릭 → OP-02

## 권한

- operator_super: 비활성화 활성
- operator_staff: 비활성화 비활성 (PRD §8 Scenario 5)
