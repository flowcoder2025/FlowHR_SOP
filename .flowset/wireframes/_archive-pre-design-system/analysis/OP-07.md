# OP-07 기능 플래그 — 와이어프레임 분석

## PRD 1:1 매핑

| PRD § | 요구 | 구현 위치 | 상태 |
|-------|------|----------|:---:|
| §3-1 테이블 8 컬럼 | 기능명/모듈/글로벌/플랜/예외/베타/적용일/액션 | `.table` | ✅ 8/8 |
| §3-2 필터 3종 | 모듈/상태/베타 | filter-bar 칩 | ✅ |
| §3-3 액션 | 기능 추가 / 글로벌 토글 / 예외 / 변경이력 | 액션 + 행 메뉴 + toggle 컴포넌트 | ✅ |
| §3-4 모달 | 기능 추가/수정 (key/라벨/모듈/플랜/베타) | 별도 모달 (Phase 6 보강) | △ |
| §5 글로벌 상태 4개 | active/inactive/beta/restricted | toggle + 베타 배지 | ✅ 4/4 |

## 토글 인터랙션

- 글로벌 ON/OFF → toggle 컴포넌트 즉시 반영 (audit_logs feature_flag.toggle 기록)
- 예외 테넌트 수 클릭 → 예외 설정 모달 (테넌트 자동완성 + ON/OFF)
- 변경 이력 → 행 액션 메뉴

## 클라이언트 평가

- 모든 클라이언트가 `GET /api/v1/feature-flags?context=tenant_id` 호출
- 머지 결과: 글로벌 + 플랜 + 예외 (예외 우선)
- Realtime broadcast로 즉시 invalidate

## 권한

- operator_super: 기능 추가/삭제 가능
- operator_staff: R/U/L만 → "기능 추가" 비활성 (PRD §8 Scenario 4)
