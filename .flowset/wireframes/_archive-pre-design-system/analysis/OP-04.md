# OP-04 신규 테넌트 등록 — 와이어프레임 분석

## PRD 1:1 매핑

| PRD § | 요구 | 구현 위치 | 상태 |
|-------|------|----------|:---:|
| §3-1 마법사 7단계 | 회사/도메인/요금제/관리자/모듈/초기데이터/완료 | 좌측 stepper | ✅ 7/7 |
| §3-2 실시간 검증 | 사업자번호/슬러그/이메일/계약인원 | 슬러그 입력 + success/error 메시지 | ✅ (현재 화면 = 2단계 슬러그) |
| §3-3 액션 | 이전/다음/임시저장/검증/등록완료/초대발송 | 헤더 임시저장 + 폼 액션 | ✅ |
| §4 액션 4개 | onSaveDraft/onNext/onSubmit/onSendInvite | 버튼 매핑 | ✅ |
| §5 상태 | step/draftId/submitting/result | stepper 시각화 (1 done, 2 active, 3-7 pending) | ✅ |

## 본 와이어프레임 = 2단계 (도메인 슬러그)

다른 단계는 폼 콘텐츠만 교체. 공통: stepper / 헤더 임시저장 / 폼 액션 (이전/다음).

각 단계별 폼 필드는 PRD §3-1 표 그대로:
1. 회사정보 (회사명/사업자번호/대표자/업종/주소/연락처/로고)
2. **도메인 슬러그** (현재 화면)
3. 요금제 + 계약 시작/종료/인원
4. 관리자 (대표 + 추가 최대 3명)
5. 모듈 토글 8개
6. 초기 데이터 (부서/근무정책/휴가/결재라인/문서양식)
7. 검토 + 등록 완료

## 검증 흐름

- 슬러그 입력 → debounce 300ms → `POST /check-domain` → 결과 표시
- 사업자번호 입력 → 형식 검증 + `POST /check-business-number`
- 이메일: 형식 + 중복 (다른 테넌트 관리자와 동일 차단)

## 임시저장

- "임시저장" 클릭 → `tenants_drafts` upsert (draftId 부여)
- 페이지 이탈 후 OP-02 알림 → 동일 draftId로 재진입 → 단계 복원 (PRD §8 Scenario 4)

## 등록 완료 (7단계)

- 트랜잭션: tenants + subscription + admin user invite + tenant_settings 모두 INSERT
- 부분 실패 (이메일 발송 실패) → status=pending_invite + "재시도" 버튼 (PRD §8 Scenario 5)
