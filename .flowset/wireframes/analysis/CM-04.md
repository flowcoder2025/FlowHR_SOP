## 1. PRD 매핑

| PRD 항목 | 구현 |
|---------|------|
| 방식: TOTP (Google Authenticator 호환) | 6자리 OTP 입력 (`.otp-group` × 6) |
| 로그인 시 흐름: 이메일/비밀번호 통과 → 6자리 입력 → 세션 발급 | input → loading → (성공 시 done / 실패 시 error) |
| 복구 코드 — 한 번 사용 시 무효, 8개 모두 소진 시 운영사 문의 | recovery 상태 — XXXX-XXXX 형식 input + "남은 7개" 표시 |
| 운영사 계정 강제 | (활성화는 CM-03/OP-12 영역, 본 화면은 로그인 입력만) |

## 2. 상태 매트릭스 (5)

| 키 | state | 설명 |
|---|-------|------|
| 1 | input | 6자리 OTP 입력 (default) |
| 2 | loading | 검증 중 (spinner) |

## 5. API 매핑 (api/auth.md)

| 액션 | 엔드포인트 |
|------|----------|
| OTP 검증 | `POST /api/v1/auth/login/two-factor` { temp_token, otp_code } → 200 (access_token + refresh_token) / 401 AUTH_2FA_INVALID |
| 복구 코드 사용 | `POST /api/v1/auth/login/recovery` { temp_token, recovery_code } → 200 + 코드 무효 처리 (서버 자동) |
| 잔여 복구 코드 조회 | `GET /api/v1/me/two-factor/recovery-status` → { remaining: 7 } |

`temp_token`: CM-01 1단계 통과 시 발급되는 짧은 만료 토큰 (5분).

## 6. 검증 (Gherkin 정합)

- ✅ 6자리 OTP 정상 입력 → done
- ✅ OTP 불일치 5회 → 잠금 (PRD spec, 본 화면은 시도 카운트 표시만)
- ✅ 복구 코드 8개 모두 소진 시 운영사 문의 (recovery 상태 안내)

추가 시각 검수:
- [ ] OTP 자동 next focus (1자 입력 시 다음 input)
- [ ] OTP 6자리 다 채우면 자동 제출 (loading → error 시뮬레이션 0.9s)
- [ ] 복구 코드 input — uppercase + monospace + 글자 간 spacing
- [ ] error 상태 — OTP input border 빨강 (border-color: danger)
- [ ] 좁은 카드(.auth-card-narrow 360px) 시각 균형

## 7. Phase 7 변환

- `react-otp-input` 또는 자체 6 input 컴포넌트
- temp_token은 sessionStorage (XSS 안전성 — Phase 7에서 httpOnly cookie 가능 여부 검토)
- recovery 사용 후 자동 무효 처리 (서버 측 transaction)
- TOTP 시간 동기 — 클라이언트 시계 30초 ±1 허용
