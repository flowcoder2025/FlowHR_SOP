## 1. PRD 매핑

| PRD 항목 | 구현 |
|---------|------|
| 경로 `/activate?token={invitationToken}` | 단일 화면, 5 상태 (state-invite/setup/two_fa/expired/done) |
| 흐름 — 초대 토큰 검증 → 비밀번호 설정 → 약관 동의 → 선택 2FA → 로그인 | 1 invite → 2 setup → 3 two_fa → 5 done (자동 로그인) |
| 토큰 7일 만료, 1회 사용 | state-invite 헤더 "6일 23시간 남음" + state-expired에서 INVITATION_EXPIRED 안내 |
| 만료 시 재발송 요청 | state-expired 카드 — "초대 메일 재발송 요청 (관리자에게)" 버튼 |
| 운영사 계정 강제 2FA | state-two_fa 헤더 "운영사 계정은 필수" / "건너뛰기 (직원)" 버튼은 직원만 노출 (라벨 분기) |

## 2. 상태 매트릭스 (5)

| 키 | state | 설명 |
|---|-------|------|
| 1 | invite | 초대 정보 확인 (이메일/이름/회사/역할/초대자/만료 표시) |
| 2 | setup | 비밀번호 설정 + 약관 동의 (이용약관/개인정보/마케팅 선택) |
| 3 | two_fa | 2FA 설정 (QR + 6자리 OTP + 복구 코드 8개) — 직원 skip 가능, 운영사 필수 |
| 4 | expired | 토큰 만료 / 이미 사용 (INVITATION_EXPIRED) |
| 5 | done | 활성화 완료, 자동 로그인 (3초 후 대시보드) |

## 5. API 매핑 (api/auth.md)

| 액션 | 엔드포인트 |
|------|----------|
| 토큰 검증 | `GET /api/v1/auth/invitation?token=...` → 200 (초대 정보) / 410 (INVITATION_EXPIRED) |
| 활성화 | `POST /api/v1/auth/activate` { token, password, consents[], two_factor_secret?, otp_code? } → 200 (자동 로그인 토큰 발급) |
| 2FA 활성화 (선택) | `POST /api/v1/me/two-factor/enable` { secret, otp_code } → 복구 코드 8개 반환 |
| 재발송 요청 | `POST /api/v1/auth/invitation/resend-request` { token } → 관리자에게 알림 |

## 6. 검증 (Gherkin 정합)

- ✅ 토큰 검증 + 정보 표시 (invite)
- ✅ 비밀번호 + 약관 (필수 2 + 선택 1) (setup)
- ✅ 2FA 권장/필수 분기 (two_fa)
- ✅ 7일 만료 + 1회 사용 (expired에서 안내 + 재발송 CTA)

추가 시각 검수:
- [ ] 5 상태 토글 (1~5 키)
- [ ] OTP 자동 next focus (input 1자 입력 시 다음으로)
- [ ] 약관 체크박스 필수/선택 라벨 명확
- [ ] QR placeholder + 시크릿 코드 + 복구 코드 8개 grid
- [ ] 건너뛰기 vs 활성화 완료 버튼 라벨 분기 (직원/운영사)
