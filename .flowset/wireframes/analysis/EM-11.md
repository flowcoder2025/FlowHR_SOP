## 6. 권한 매트릭스

- `employee`: R/Cancel/Resubmit 본인 (state=default)
- 다른 직원의 요청 → 403 (각 entity의 RLS)
- MVP에서는 router middleware로 EM-11 진입 시 EM-05로 redirect (Phase 7) — 본 와이어프레임은 v1.1 시안

## 7. 검증

- [ ] 5 상태 — default v1.1 미리보기 / loading / empty / mvp 큰 warning card / error
- [ ] 상단 banner — default = info v1.1 안내 + EM-05 이동 CTA
- [ ] MVP 안내 — warning card 큰 사이즈 + EM-05 CTA + 하단 req-content 흐림 (opacity 0.5 비활성)
- [ ] 필터 3 select-wrap 적용
- [ ] 테이블 7 컬럼 + 유형 5종 (휴가/근태/증명서/정보 변경/문서) + 상태 다양 배지
- [ ] 반려 row — 재요청 버튼 활성
- [ ] 사이드바 active=결재 (EM-05) — EM-11 별도 메뉴 없음 (MVP 정합)
- [ ] Playwright smoke — iconInvisible 0

## 8. Phase 7 변환

- v1.1 진입 — `/me/requests` route 활성 + 사이드바에 EM-11 메뉴 추가
- MVP middleware — `users.tenant_feature_flag.unified_requests === false` → `redirect('/me/approvals')`
- 통합 view — 서버 측 4 테이블 UNION (`leaves` / `attendance_modifications` / `certificate_requests` / `employee_change_requests`) + Approval JOIN
- 카테고리별 정렬/필터 — `?type=leave,certificate&status=in_progress`
- 재요청 — 각 entity의 prefill 라우터 (EM-03/08/09)

## 9. 의존성

- **선행**: EM-05 (MVP 통합), 모든 요청 화면 (EM-03/EM-08/EM-09/TA-06)
- **연계**: v1.1 도입 시 EM-05와 카테고리 분리 — EM-05는 결재 중심, EM-11은 통합 카탈로그
- **MVP**: 본 화면은 v1.1로 유보, MVP는 EM-05로 통합 — 사이드바 비표시 + router redirect
