# CM-02 비밀번호 찾기 — Wireframe Analysis

> **소스**: `wireframes/html/CM-02.html`
> **PRD**: `prd/domains/common.md §CM-02`
> **레이아웃**: `_design-system/_layout-auth.html` (비인증)
> **작성**: 2026-05-16 (G1 wf-v0.1.0 양산)

## 1. PRD 매핑

| PRD 항목 | 구현 |
|---------|------|
| 경로 `/forgot-password` + `/reset-password?token=` | 단일 화면(CM-02.html) 2단계 통합 — state-step1/step2 |
| 흐름: 이메일 → Supabase resetPasswordForEmail → 메일 링크 → 새 비밀번호 | step1 → sent → (메일링크) → step2 → done |
| 등록 안 된 이메일에도 동일 메시지 | `sent` 상태 — "입력하신 이메일이 등록되어 있으면 안내 메일을 받게 됩니다" (계정 존재 여부 노출 방지) |
| 토큰 만료 60분 | step2 헤더 "남은 시간 52분" 표시 + `expired` 상태에서 AUTH_RESET_TOKEN_EXPIRED 안내 |
| 재설정 후 모든 활성 세션 무효화 | step2 카드 하단 warning banner — "모든 활성 세션이 무효화됩니다" |

## 2. 상태 매트릭스 (5)

| 키 | state | 설명 |
|---|-------|------|
| 1 | step1 | 이메일 입력 (default) |
| 2 | sent | 발송 안내 (성공/계정 존재 여부 노출 방지) |
| 3 | step2 | 새 비밀번호 입력 (토큰 검증 OK, 남은 시간 표시) |
| 4 | expired | 토큰 만료 (AUTH_RESET_TOKEN_EXPIRED) |
| 5 | done | 재설정 완료 (모든 세션 무효화 안내 + 로그인 이동 CTA) |

## 5. API 매핑 (api/auth.md)

| 액션 | 엔드포인트 |
|------|----------|
| step1 발송 | `POST /api/v1/auth/forgot-password` { email } → 200 (항상 동일 응답) |
| step2 재설정 | `POST /api/v1/auth/reset-password` { token, new_password } → 200 / 410 RESET_TOKEN_EXPIRED |
| 세션 무효화 | 재설정 성공 시 서버 측 `revoke_all_sessions(user_id)` 자동 호출 |

## 6. 검증 (Gherkin 정합)

- ✅ 등록되지 않은 이메일 → 동일 메시지 (sent 상태)
- ✅ 토큰 60분 만료 → expired 상태 + 재요청 CTA
- ✅ 재설정 후 모든 활성 세션 무효화 안내 (step2 warning banner)

추가 시각 검수:
- [ ] 5 상태 토글 정확 (state-step1 디폴트)
- [ ] 비밀번호 정책 met/unmet 색상 (success / muted)
- [ ] step2 카드 안 비밀번호 필드 2개 (입력 + 확인)
- [ ] 이메일 발송 시뮬레이션 — 버튼 클릭 시 0.7s 후 sent 자동 전환

## 7. Phase 7 변환

- React-Hook-Form + zod schema (`forgotEmailSchema`, `resetPasswordSchema`)
- step 상태는 react state 또는 URL `?step=`
- 메일 링크 클릭 시 token URL param 검증 → step2 자동 진입
- 비밀번호 정책 실시간 검증 (zod refine + watch)
