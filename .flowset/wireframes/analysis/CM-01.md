## 3. 상태 매트릭스 (4 + 1)

| 상태 | URL | 키 | 알림 | 폼 상태 | 캡차 |
|------|-----|-----|------|---------|------|
| default | `?state=default` | `1` | (없음) | 활성 | 미노출 |
| loading | `?state=loading` | `2` | (없음) | 버튼 spinner + pointer-events:none | 미노출 |
| error | `?state=error` | `3` | "이메일/비밀번호 오류 · 남은 시도 2회" (AUTH_INVALID_CREDENTIALS) | 활성 | 미노출 |
| locked | `?state=locked` | `4` | "5회 실패 잠금 · 04:32 후 재시도" (AUTH_LOCKED) | 비활성 (input opacity 0.7) | **노출** |
| success | `?state=success` | `5` | "1단계 완료 · CM-04로 이동…" (AUTH_2FA_REQUIRED) | 활성 | 미노출 |

JS 동작:
- 로그인 버튼 클릭 → `applyState('loading')` → 1.4s 후 `applyState('error')` (실패 시뮬레이션)
- URL `?state=` ↔ `body[data-state=]` 양방향 동기화
- 키보드 `1~5` 단축키 (input/textarea focus 시 무시)
- 디버그 패널 클릭으로도 전환

## 4. 라우팅 동선 (09-routing.md §3)

```
사용자 진입 /login
  ↓
[이메일 + 비밀번호 입력]
  ↓
POST /api/v1/auth/login
  ├── 200 + role=operator  → /operator (OP-01)
  ├── 200 + role=tenant_*  → /admin (TA-01)
  ├── 200 + role=employee  → /me (EM-01)
  ├── 200 + 2fa_required   → /2fa (CM-04) — state=success
  ├── 401 INVALID_CREDS    → state=error (재시도 카운트 표시)
  ├── 423 LOCKED           → state=locked (5분 카운트다운 + 캡차)
  └── 5xx                  → /500 (CM-06)
```

`return_url` 파라미터: 세션 만료 진입 시 `/login?return_url=/admin/employees`. 로그인 성공 후 `return_url` 우선 이동 (09-routing §5).

## 6. API 매핑 (api/auth.md)

| 액션 | 엔드포인트 | 응답 분기 |
|------|----------|---------|
| 로그인 | `POST /api/v1/auth/login` | 200 (role + locale + access_token + refresh_token), 401 (AUTH_INVALID_CREDENTIALS), 423 (AUTH_LOCKED), 200 + `two_factor_required: true` (AUTH_2FA_REQUIRED) |
| 비밀번호 찾기 진입 | navigate → `/forgot-password` | CM-02 |
| 계정 활성화 진입 | navigate → `/activate?token=...` | CM-03 |
| 2FA 입력 | navigate → `/2fa` | CM-04 (POST /api/v1/auth/login/two-factor) |

응답에 `user.locale` 포함 — locale 결정 우선순위(api/auth.md L? batch-005): URL ?lang → user.locale (DB) → Accept-Language → 'ko' default.

## 7. 검증 (Gherkin 정합)

PRD §CM-01 Gherkin 3 시나리오 모두 와이어프레임에서 표현됨:

```gherkin
✅ 정상 로그인 → default → loading → (역할별 대시보드 navigate)
✅ 5회 실패 후 잠금 → error (시도 카운트 감소) → locked (5분 + 캡차)
✅ 2FA 활성화 사용자 → success (CM-04 진입 안내)
```

추가 시각 검수 항목 (사용자 의무):
- [ ] 4 상태 토글 전환 시 카드 높이 변화 부드러움 (점프 X)
- [ ] 비밀번호 보이기 토글 — eye / eye-off 아이콘 정확
- [ ] 언어 토글 클릭 시 한국어 ↔ English 위치 교환
- [ ] 캡차 박스가 locked 상태에서만 노출
- [ ] 모바일 (≤768px) — 카드 16px 패딩, 푸터 column 정렬

## 8. Phase 7 Next.js 변환 가이드 (07-react-mapping.md §1, §8)

```tsx
// app/login/page.tsx (App Router)
'use client';
import { useTranslations } from 'next-intl';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const loginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  remember: z.boolean(),
});

export default function LoginPage() {
  const t = useTranslations('auth.login');
  const { register, handleSubmit, formState: { isSubmitting } } = useForm({
    resolver: zodResolver(loginSchema),
  });
  // ... 폼 + 상태 (replaceState X — react state로 default/loading/error/locked/success)
}
```

상태는 `useState<'default' | 'loading' | 'error' | 'locked' | 'success'>`로 관리. URL ?state=는 개발자 단축키 제거. 키보드 1~5 비활성. 디버그 패널 제거.
