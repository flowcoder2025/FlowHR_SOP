## 5. API / 운영 매핑

| 상태 | 트리거 |
|------|-------|
| 404 | Next.js notFound() 또는 라우터 fallback |
| 500 | 서버 throw + Sentry capture + request_id 응답 |
| maintenance | OP-11 시스템 설정에서 토글, `system_settings.maintenance_mode = true` 시 미들웨어가 모든 요청 인터셉트 (operator_super 제외) |
| 503 | rate-limit 또는 upstream 장애 — retry_after 헤더 |
| network | axios/fetch error event — offline 이벤트 |

### 구현 결정 (codex 협의 A안)

- **점검 데이터 소스**: `maintenance_windows` 테이블(status enum: inactive/scheduled/active) — `system_settings.maintenance_mode` 대신 채택. RLS `maintenance_windows_read using(true)` 공개 읽기.
- **우회 범위**: `operator_super` 만 우회(PRD §CM-06 + 핸드오프 SSOT). 로그인(`/login`)·점검 페이지(`/maintenance`)는 점검 중에도 접근 허용(operator 인증 동선 보존).
- **503 방식**: `NextResponse.rewrite(/{locale}/maintenance, {status: 503, Retry-After})` — URL 유지 + 503 상태 + 점검 페이지 본문.
- **message_ko**: 운영사 작성 ko 본문을 "운영사 안내" 블록으로 표시(제목/기본 안내는 locale i18n). en 본문 컬럼 부재 — KI 등록.
- **남은 카운트다운**: 클라이언트 컴포넌트(시간 의존, SSR/CSR 불일치 회피 위해 마운트 후 채움).

### 미구현/유보 (KI 등록)

- `state-service_unavailable`(과부하 503 retry_after) / `state-network`(오프라인) 상태 — 클라이언트 회복탄력성(fetch interceptor/offline 리스너) WI 로 유보(ST-072 AC 범위 외 와이어프레임 확장).
- 점검 상태 미들웨어 매 요청 조회(TTL 15s 캐시 완화) → Realtime `realtime:maintenance` 무효화/edge-config 캐시는 후속.
- 점검 자동 E2E(active 토글)는 staging 시드 setup/teardown 필요 — 비활성 경로 E2E + staging 수동 실증으로 핵심 커버.
