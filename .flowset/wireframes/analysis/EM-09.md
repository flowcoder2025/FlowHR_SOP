## 5. API 매핑

```
GET   /api/v1/me/profile
PATCH /api/v1/me/profile                     # 즉시 수정 (허용 필드만 — 닉네임/주소/비상)
POST  /api/v1/me/profile/change-requests     # HR 승인 필요 (이름/계좌/가족)
GET   /api/v1/me/profile/change-requests
POST  /api/v1/me/security/change-password
POST  /api/v1/me/security/2fa/enable         # → QR + 복구 코드
POST  /api/v1/me/security/2fa/verify
POST  /api/v1/me/security/2fa/disable
GET   /api/v1/me/security/sessions
DELETE /api/v1/me/security/sessions/:id
POST  /api/v1/me/avatar
```

## 6. 권한 매트릭스

- `employee`: R/U 본인 (즉시 수정 = 닉네임/주소/비상연락처, 변경 요청 = 이름/계좌/가족)
- 계좌 변경 → 2FA 재인증 + HR 승인 흐름
- 가족정보 변경 → HR 승인 (4대보험 영향)
- 보안 탭 — 본인만 변경 가능
- 비밀번호 변경 시 → 다른 모든 세션 무효화
- 2FA 비활성화 시 → 보안 경고 + 재확인 모달 (Phase 7)

## 8. Phase 7 변환

- React Hook Form + Zod 분기 (`ProfileBasicSchema`, `ProfileBankSchema`, `ChangePasswordSchema`)
- 2FA — `otplib` 또는 Supabase Auth 2FA + QR (`qrcode.react`) + 복구 코드 8개 발급
- 활성 세션 — Supabase Auth `sessions` 테이블 또는 `auth.refresh_tokens` 조회
- 비밀번호 변경 시 → Supabase Auth `updateUser({ password })` + 다른 세션 sign out (`signOutOtherSessions()`)
- 변경 요청 — `employee_change_requests` INSERT (`field`, `new_value`, `status='pending'`) → HR 검토 → 승인 시 `employees` UPDATE
- 프로필 사진 — Supabase Storage `avatars/employee-{id}/{uuid}` + crop client-side (Cropper.js)
