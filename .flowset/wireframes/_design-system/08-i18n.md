# 08. i18n (다국어 ko + en MVP)

> **MVP 정책 (2026-05-16 사용자 결정)**: 한국어(`ko`) + 영어(`en`) 동시 지원. 외국인 근로자 사용성 핵심.
> 스택: next-intl 3.x (PRD 03-tech-architecture L23). 통화 KRW / 시간대 Asia/Seoul 고정 (한국 사업장).
> 페르소나: P8 Nguyen 외국인 근로자 (PRD 01-personas).

## 1. 정책

### 1-1. 지원 언어
- `ko` (한국어, default)
- `en` (English, 외국인 근로자)
- 기타 언어(중국어/베트남어 등)는 v1.2+ 추가 가능 — i18n 인프라가 이미 다국어 대응이라 키 추가만으로 확장

### 1-2. locale 결정 우선순위 (api/auth.md §i18n locale 처리)
1. `users.locale` (DB 명시값)
2. 첫 로그인 → `Accept-Language` 헤더 (`ko-KR`/`ko` → ko, `en-*` → en, 기타 → ko)
3. default `ko`

### 1-3. 고정 텍스트 정책
모든 사용자 화면 텍스트는 i18n 키로 추출. 와이어프레임 단계에서는 한글로 명시 + Phase 7 React 변환 시 키 추출.

| 위치 | 처리 |
|------|------|
| **컴포넌트 자체 텍스트** (CTA "취소"/"확인"/"다음", "이전 화면", placeholder, error message) | `messages/{locale}/components.json` 공용 키 |
| **화면별 도메인 텍스트** (페이지 타이틀, KPI 라벨, 행 컬럼명) | `messages/{locale}/screens/{screen-id}.json` |
| **시스템 메시지** (banner/toast/error/empty state) | `messages/{locale}/system.json` |
| **알림 본문** (인앱/푸시/카카오/SMS/이메일) | `messages/{locale}/notifications.json` + 이메일 템플릿 별도 (`templates/{id}.{locale}.tsx`) |
| **enum 라벨** (status, type 등) | `messages/{locale}/enums.json` (db/enums.md 영문 키 → 라벨 매핑) |
| **사용자 입력 데이터** (회사명, 직원명, 휴가 사유 등) | i18n 미적용 — DB 그대로 표시 |
| **법적 효력 있는 약관** (CM-21) | LegalDocument 엔티티 + language 필드 — ko가 법적 효력, en은 참고 번역 |

### G1 비인증 영역 도메인 키 (CM-01~04, CM-20, CM-21)

비인증 화면은 `screens.cm-XX.*` 화면 단위 외에 **도메인 네임스페이스 병용 허용** — 인증/법적 문서/설치 가이드는 도메인 단위 재사용성이 높아 공통 키로 추출.

| 도메인 | 네임스페이스 | 사용 화면 |
|--------|------------|----------|
| 인증 (로그인/비밀번호 찾기/활성화/2FA) | `auth.{login|forgot|activate|two_fa}.*` | CM-01 / CM-02 / CM-03 / CM-04 |
| 법적 문서 | `legal.{terms|privacy|consent}.*` | CM-21 |
| PWA 설치 가이드 | `install.{ios|android|desktop|ios_old|already_installed}.*` | CM-20 |
| 공통 필드 라벨 | `common.field.{email|password|name|otp_code|recovery_code}` | 인증 화면 전반 |

`screens.cm-XX.*`로 화면 한정 텍스트 + 도메인 키로 재사용 가능 텍스트 분리. 충돌 시 `screens.*`가 우선 (catalog 단일 SSOT 원칙).

## 5. 화면별 i18n 키 추출 정책

각 화면 React 컴포넌트는 `useTranslations('screens.{screen-id}')`로 키 사용:

```tsx
// apps/web/app/(operator)/page.tsx (OP-01)
'use client';
import { useTranslations } from 'next-intl';

export default function Dashboard() {
  const t = useTranslations('screens.op-01');
  return (
    <h1>{t('title')}</h1>
    <KpiCard label={t('kpi.totalTenants')} value={47} />
    ...
  );
}
```

키 추출 의무:
1. PRD §3 화면 명세에 등장하는 모든 표시 텍스트
2. PRD §4 액션 라벨
3. PRD §5 상태값 (enum 키 — db/enums.md 매핑 + i18n labels)
4. 헤더 페이지 타이틀
5. 테이블 컬럼 헤더
6. 필터 라벨 + 옵션
7. 빈 상태 / 에러 메시지

화면 명세 파일(`prd/domains/.../{screen-id}-*.md`)에서 모든 텍스트 추출 → `messages/{locale}/screens/{screen-id}.json` 자동 생성 (Phase 7 빌드 스크립트).

## 8. Phase 7 React 변환 (07-react-mapping.md §i18n)

### 8-1. next-intl 설정
```ts
// apps/web/i18n/request.ts
import { getRequestConfig } from 'next-intl/server';
import { headers, cookies } from 'next/headers';

export default getRequestConfig(async () => {
  // 우선순위: 1) cookie locale → 2) Accept-Language → 3) ko default
  const locale = cookies().get('locale')?.value
    || matchAcceptLanguage(headers().get('accept-language'))
    || 'ko';

  return {
    locale,
    messages: (await import(`../../packages/i18n/messages/${locale}/index.ts`)).default,
  };
});
```

### 8-2. layout.tsx
```tsx
import { NextIntlClientProvider } from 'next-intl';
import { getLocale, getMessages } from 'next-intl/server';

export default async function Layout({ children }) {
  const locale = await getLocale();
  const messages = await getMessages();

  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider locale={locale} messages={messages}>
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

### 8-3. locale 변경 (CM-16 메뉴)
```tsx
async function changeLocale(newLocale: 'ko' | 'en') {
  await fetch('/api/v1/me/profile', { method: 'PATCH', body: JSON.stringify({ locale: newLocale }) });
  document.cookie = `locale=${newLocale}; path=/; max-age=31536000`;
  window.location.reload();
}
```
