# 01. 페르소나 / 사용자 여정

## 1. 권한 구조 (spec §3 인용)

| 역할 코드 | 한글명 | 설명 | 주요 책임 |
|----------|--------|------|---------|
| `operator_super` | 운영사 최고관리자 | FlowHR 운영자 | 테넌트/요금제/청구/기능권한/지원/로그/리포트 전권 |
| `operator_staff` | 운영사 일반관리자 | FlowHR 운영팀 | 테넌트 운영 + 티켓 응대 |
| `tenant_super` | 테넌트 최고관리자 | 고객사 대표/관리자 | 회사 설정/직원/근태/휴가/결재/급여 전권 |
| `tenant_hr_admin` | HR 관리자 | 고객사 HR 담당자 | 직원·근태·휴가·급여·문서 운영 |
| `tenant_manager` | 팀장 / 결재권자 | 고객사 부서장·결재권자 | 소속팀 근태·휴가 승인 |
| `employee` | 직원 | 일반 사용자 | 출퇴근·휴가 신청·문서 조회 |

## 2. 페르소나 상세

### P1. 운영사 — 김운영 (FlowHR PM, `operator_super`)

| 항목 | 내용 |
|------|------|
| 역할 | FlowHR 운영자 — 신규 고객 온보딩, 청구, 장애 대응 |
| 사용 빈도 | 매일 (업무시간 내) |
| 주요 디바이스 | Web (Desktop) + Tauri Desktop |
| Pain Point | 고객사마다 다른 조직도/근무제 세팅 소요시간, 미납 추적 누락, 장애 대응 지연 |
| 성공 정의 | 신규 테넌트 온보딩 ≤ 2시간, 미수금 ≤ 5%, 티켓 SLA 24h 이내 |
| 주요 화면 | OP-01 ~ OP-11 + TA-* 시뮬레이션 |

### P2. 운영사 — 박오퍼 (FlowHR 운영 스태프, `operator_staff`)

| 항목 | 내용 |
|------|------|
| 역할 | 고객 문의 응대, 청구 보조, 시스템 모니터링 |
| 사용 빈도 | 매일 |
| 주요 디바이스 | Web |
| Pain Point | 티켓 응대 중 권한 부족으로 매번 김운영에게 이관 |
| 성공 정의 | 1차 응대 90% 자체 해결, 평균 응답 시간 ≤ 2h |

### P3. 테넌트 관리자 — 이대표 (고객사 대표, `tenant_super`)

| 항목 | 내용 |
|------|------|
| 회사 규모 | 직원 30명, 음식점 체인 |
| 역할 | 회사 운영 + HR 결재 최종 승인 |
| 사용 빈도 | 주 2~3회 (결재 시) |
| 주요 디바이스 | PWA (모바일) — 외근 중 결재 |
| Pain Point | 카톡으로 결재 받다 보니 누락, 휴가 잔여 직원마다 모름 |
| 성공 정의 | 결재 평균 처리시간 ≤ 4시간, 휴가 분쟁 0건 |

### P4. 테넌트 관리자 — 정인사 (HR 담당, `tenant_hr_admin`)

| 항목 | 내용 |
|------|------|
| 역할 | 30명 직원의 근태·휴가·급여명세서·계약서 관리 |
| 사용 빈도 | 매일 |
| 주요 디바이스 | Web (Desktop) — 사무실 데스크톱 |
| Pain Point | 엑셀로 근태 집계, 월말 급여명세서 인쇄 후 직접 배부, 4대보험 변경 추적 |
| 성공 정의 | 월말 급여명세서 발송 1일 단축, 근태 이상자 즉시 알림 |
| 주요 화면 | TA-01 ~ TA-14 |

### P5. 테넌트 관리자 — 최팀장 (팀장 / 결재권자, `tenant_manager`)

| 항목 | 내용 |
|------|------|
| 역할 | 팀원 5명의 근태·휴가 1차 승인 |
| 사용 빈도 | 매일 (모바일 알림 기반) |
| 주요 디바이스 | PWA (모바일) |
| Pain Point | 팀원 휴가 신청 카톡으로 받아 잊어버림 |
| 성공 정의 | 결재 알림 무시율 ≤ 5%, 결재 평균 ≤ 2시간 |

### P6. 직원 — 한직원 (정규직, `employee`)

| 항목 | 내용 |

| 사용 빈도 | 매일 출퇴근, 주 1~2회 휴가/조회 |

| Pain Point | 출퇴근 카톡으로 보고, 휴가 종이결재, 급여명세서 종이 수령 |
| 성공 정의 | 출근/퇴근 1탭, 휴가 신청 30초, 급여명세서 즉시 조회 |
| 주요 화면 | EM-01 ~ EM-11 |

### P8. 직원 — Nguyen (외국인 근로자, `employee`) — i18n MVP 핵심 페르소나

| 항목 | 내용 |
|------|------|

## 3. 사용자 여정 (Top 3)

### J1. 신규 테넌트 온보딩 (운영사 김운영 + 테넌트 이대표)

```
김운영: OP-04 신규 테넌트 등록 → 회사정보·도메인·요금제·관리자계정·모듈선택·초기데이터 7단계 입력
   ↓
시스템: 이대표 이메일로 초대 발송
   ↓
이대표: 초대 메일 클릭 → 최초 계정 활성화 (비밀번호 설정 + 약관 동의 + 2FA 설정)
   ↓
이대표: TA-13 회사 설정 → 김운영이 미리 세팅한 조직도/근무제/휴가정책/결재라인/문서양식 확인
   ↓
이대표: TA-02 직원 관리 → 일괄 업로드(엑셀) 또는 개별 초대
   ↓
직원들: 초대 메일 → 계정 활성화 → 출퇴근/휴가 사용 시작
```

성공 기준: 김운영 작업 시간 ≤ 2시간, 이대표 첫 로그인부터 직원 초대까지 ≤ 30분.

### J2. 직원 휴가 신청 → 결재 → 차감 (한직원 + 최팀장 + 이대표)

```
한직원: EM-01 대시보드 → 잔여연차 확인 → EM-03 휴가 신청 (유형/시작/종료/사유/대체근무자 입력)
   ↓
시스템: 결재라인(최팀장 → 이대표) 자동 적용, 최팀장에게 푸시/카카오 알림
   ↓
최팀장: 알림 클릭 → PWA에서 TA-08 휴가 신청 상세 → 승인
   ↓
시스템: 이대표에게 알림
   ↓
이대표: 알림 클릭 → 외근 중 PWA에서 승인
   ↓
시스템: Leave 상태 = 승인 완료, 잔여연차 차감, 한직원에게 알림, 캘린더 반영
   ↓
한직원: EM-04 내 휴가 현황에서 사용일수/잔여 확인
```

성공 기준: 신청부터 최종 승인까지 평균 4시간 이내, 잔여연차 자동 차감 정확도 100%.

### J3. 월말 급여명세서 배포 (정인사 + 한직원)

```
정인사: TA-10 급여/문서 관리 → 급여명세서 탭 → 엑셀 업로드 (모든 직원의 지급/공제 항목)
   ↓
시스템: 직원별 PDF 자동 생성, 정인사에게 미리보기 제공
   ↓
정인사: 일괄 발송 클릭 → 시스템이 직원별 알림 + 이메일 발송
   ↓
한직원: EM-10 알림함 또는 푸시 → EM-06 급여명세서 조회 → 열람 확인 + PDF 다운로드
   ↓
정인사: TA-10에서 열람 상태(미열람/열람 완료) 모니터링, 미열람자 재발송
```

성공 기준: 업로드부터 첫 직원 열람까지 ≤ 1시간, 월말 미열람율 ≤ 5%.
